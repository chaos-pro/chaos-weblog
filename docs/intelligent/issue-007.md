# AI写代码，用户和开发者都慌？



最近一段时间特别忙，所以和社媒有点脱节，忙完再来浏览关注的AI领域，发现自己有点看不懂。

**当AI行业缺乏客观的热点，社媒就会主观的带节奏。**

比如聊点安全问题，分析一下未来的趋势，或者来个行业发展总结，总之不能放过自带流量的话题。

**DeepSeek模型的V4版本，未发布都能偶尔上热搜。**

互联网赛道里的民工，最关注的自然是AI编程，也是大模型厂商最卷的方向，OpenAI甚至关停Sora应用。

**都想在编程领域，缩短和Claude之间的差距。**

为什么猛卷AI编程？自然是需求和市场，都具备相当大的确定性。

在互联网上升周期，如果产品验证市场成功，企业自然招兵买马抢业务，而在当下的趋势中，AI正加速降本增效的进程。

海量的开源项目和代码，为模型的训练提供语料，核心的数据结构和算法，是计算机擅长的维度，专注于此的Claude模型，已经交出了高分答卷。

用AI写代码做产品，个人和企业的付费意愿都很高。

社媒上App和应用层出不穷，更多是在展现想法和创意，有热度且能持续的虽不多，但不妨碍大家尝试的热情，所谓的超级个体越来越多，全栈工程师的需求越来越大。

内容和代码又具备杠杆效应，Claude模型两大能力，堪称踩到时代的痛点。

互联网上自然不缺讨论声，几个极具代表性的观点：AI不能维护屎山代码，AI正在杀死软件，AI代码的安全问题。

**甚至说AI操作手机，可以节省用户的时间。**

只要你的生活，没被互联网彻底裹挟，就清楚这些说法，在当下想来有多离谱，不过从传播效应来说，倒也值得大家吐槽和借鉴。

先说程序中的屎山代码，形成的原因非常简单，只要团队持续的换人和开发，推翻和迭代的需求也像山一样，需求远比代码更抽象，这是无法避开的问题。

**AI编程的能力毋庸置疑，但提示词上下文未必能写清需求。**

AI是否会杀死软件真不好说，不过可以确定的现状是，AI逐渐进入原生的软件系统，智能体在越来越多的场景应用，很多人用AI开发自己的工具。

人工智能的发展不会停止，个人也不能停留在围墙原地。

大量的使用AI写代码，会带来各种安全问题，这一点倒是毋庸置疑，软件工程并非只有编程，从业务边界到架构设计，从数据库管理到服务器维护，每个环节都存在安全风险。

时间和成本，与质量天然冲突，谁能想到两年时间，编程的门槛被AI无限削低。

**原本几个月入门的技能，现在几天就能用起来。**

至于让AI接管手机，每天替用户节省那几分钟，其实App运营方也能做到，广告窗口少弹几个就行，问题是省下的几分钟，用来指挥AI干活吗？

**今年的互联网氛围，都开始怀念2016年，没有AI和短视频的生活。**

当下大模型都在卷编程赛道，虽然Anthropic的封号机制令人讨厌，但从Claude产品本身来说，它的写作和编程能力确实惊艳。

在人工智能的浪潮中，反焦虑的最好方式，就是用几款趁手的AI工具。

**保持自己对AI能力的专业判断。**

当然更好的办法是：多关注客观的常识，适当的远离信息流轰炸，生活自然也会清静许多，过去忙碌的一周，AI也没用上几次。
