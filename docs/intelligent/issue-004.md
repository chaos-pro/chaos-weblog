# AI做产品，什么最重要？



最近几天用AI编程做各种产品，有偏向设计类的网页，有偏向工具类的产品，还有随手测试代码的案例，前后完成好几个想法。

**短短的几天时间，用完一个月的额度。**

在聊具体的细节之前，需要先说下自己的情况，避免引起误会性的争议：

作为互联网行业的民工，对产品和编程的技术栈，有足够详细的了解，**在AI IDE中使用Claude Opus4\.5模型，其它的用起来不顺手。**

**连续用一段时间后，即熟悉AI编程的能力，也可以看清自己的短板。**

如果想客观的认识AI做产品的水平，要尝试当下最好用的工具和模型，这样才能得到准确的结论，不同模型的能力差距十分明显。

**先说自己的理解：AI可以做复杂的产品，不过有很高的使用门槛。**

当你用AI去写产品时，最少要从两个角度思考，虽然下限不算太高，但其中要考虑的细节却不少，还需要不同专业的技能组合，故而上限非常高。

**第一是清晰的想法，第二是合理的流程。**

当然也可以试试，让AI写点破碎的氛围感，你不说也不让它问，全凭感觉发挥。

**先来说最重要的想法**，要清楚做什么类型的产品，具体的功能模块有哪些，产品布局和视觉效果如何搭配，最好把技术栈也直接敲定。

如果只有产品想法，其它的一概不知，可以在对话中先完善这一步。

**再来说流程怎么设计**，AI目前和职场现状差不多，更多时候只想着完成任务，时间少任务重的情况下，只能选择先敷衍着执行，实在忙不完只好宕机摆烂。

所以要先把想法，拆成可执行的任务，然后开发一步验收一步，这样才能事半功倍。

从自己的实际操作来说，这两步走的扎实，AI做的产品自然有模有样，不过雕琢细节和质感，就不单纯是AI能解决的问题。

也尝试过用AI处理，但碍于个人能力，效果并不是很好。

从想法到简单的产品，只是功能描述和交互逻辑，不过视觉层面的质感，还是需要专业的设计师操刀，否则产品就像粗制滥造，很多时候只能上传截图，让AI自行分析和参考。

**审美的眼光和表达能力，这个门槛可比编程高得多。**

单纯用AI做出想法的框架，整个过程简单又高效，在AI工具中一句一句的指挥都行，但简单的轮廓出来后，想要产品功能好用，还是需要耐心和时间，从细节处慢慢拔高。

**再聪明的AI也是一样，你不给出具体的指令，它也不会做的面面俱到。**

还有一个不得不提的问题，AI编程最大的反对声音，就是写的代码难以维护，当代码足够多的情况下，就算是自己写的也不好维护，所以需要AI写好注释，保持项目文档的更新。

关键的差异在于：如果追求的是代码本身，亲手敲才是最快的提升方式。

使用Claude Opus4\.5模型做产品，从视觉搭配到产品功能，以及写代码的标准程度，只要自己给出清晰的指令，它能呈现出落差不大的效果，有时候也会高出预期。

这已经足够证明，AI能做好很多事情。

如果给标准的设计稿和原型图，质量和效率还能提高。

**但是产品的成功与否，不在于背后是谁在研发，而是在于它所聚合的业务，究竟能让多少用户使用，业务和用户资源，哪一样都不可多得。**

把产品做成，比怎么做产品更难。

这也是AI编程赛道，从人工智能脱颖而出的原因，在产品不复杂的初期，提升研发的效率，降低验证市场的时间成本，还有就是代码编写的规则，可能AI更容易掌握规律。

人工智能不过刚火几年，展现的能力是惊艳的一面。

从心底里认为，也许不久的将来，你需要做什么产品，可能就是几句话的描述，AI就能快速的捏出来，甚至不需要搭建产品，在对话框里就地解决。

**它的进步速度，就是恐怖的另一面。**
