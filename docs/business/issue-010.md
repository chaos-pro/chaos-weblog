# 重新理解企业的内部协作



**尊重常识，敬畏前因后果。**



**1**



在产品领域有个常识，用户越多越难迭代，因为每个细节的改动，都会影响不同人群的体验，超级App的简单升级，会被社媒放大观察。

新版体验好不会夸，体验差容易骂上热搜。

不过有个反常识的领域，企业内部的协作产品，不管使用的员工多与少，几乎都是骂骂咧咧提需求，前期落地和中期迭代，每个版本都不容易。

**分工明确的组织内，能看见门但看不见墙。**

初创型小团队人数少，内部协作几乎是当面交流，更多专注在用户产品上，尽快实现收支平衡，才是活下去和发展的基础。

当下人工智能的浪潮中，个体加AI助手的一人公司模式，协作也并没有消失，只不过效率和形式在变化。

随着企业人数的增加，内部的协作和管理愈发重要。

在过去的互联网进程里，大部分企业实现信息化，少部分完成数字化管理，近两年开始智能化探索，追求降本增效的路从未停下。

**也有不赶趟的企业，想直接跨越三步吃红利。**

三个阶段的目标和预期是：企业内部的协作和产品，完成线上和云端管理，不同部门间协作顺畅，产品系统之间全部打通，在AI能力的基础之上，业务能高效甚至自动运转。

不管成本降得多低，效率升得多高：

组织内部的协作效能，都是企业持续面对的一个难题，**业务的任何场景，都不如人心复杂多变**。



**2**



分析一个常规流程：销售找到客户完成签约，运营人员推动服务过程，财务分析投入与营收，从流程看可以线上管理。

然而真正的情况却是：销售不想更新客户线索，运营不会提供自己的策略，财务要求结算高度自动化，管理者还整天琢磨，基于模型分析流程的效能。

**每个环节的用户，既有需求又存在私心。**

企业内部的产品设计再精妙，也很难丝滑穿透人与人之间的那堵墙，更别说是部门和部门之间，其中存在需求和人心的双重复杂。

**公司快速发展的过程，可以容忍很多问题存在。**

当核心业务进入瓶颈期，问题会进入管理者的视线，比如打工人头疼的现象，领导闲下来总想抓考勤打卡。

**难得正常点的公司，业务瓶颈期专注质量和效能。**

还有一种真实的情况，因为内部协作不流畅，导致业务不能高效运营，各部门和员工之间，经常出现甩锅的现象，不但闹心还耽误事。

组织内部协作线上管理，流程和问题更容易可视化，当下还有AI协助分析和决策，预期很美好但过程很曲折。

互联网公司的内部系统，有的采购第三方，围绕业务才会定制研发。

想让组织的协作模式，与各个系统的端到端配合，把流程和数据在线管理，能够把核心的资源留在系统内，还能提升协作的效率，不过关键的矛盾在于：

**数字化对公司有利，但部门和员工并不关心。**



**3**



十年的职场经历中，发展到一定规模的公司，推动内部数字化管理，**最终的效果，都没达到最初的预期**。

**但往正确的方向走，慢一点也勉强接受。**

其中一家互联网企业，数字化管理是公司的战略，所有流程几乎都被线上化。

唯独优质的商业线索拿不到，因为每一条的单价都高，管理层甚至恩威并行，线索数据录入系统有奖励，被应用到具体项目有提成，长期不提供线索数据，会收到批评甚至刀绩效。

**用老板当时的话说：从商务手里买数据。**

虽然过程依旧很曲折，但实现不同系统端到端连接，在行业的趋势反转中，公司至少做到了平稳过渡。

另一家制造业公司，财大气粗资源好，发展过程不关注信息化管理，导致部门协作效率低下。

**管理层推动数字化转型，就如同在凿冰山一样。**

第三方系统不好用，独立研发的时间成本太大，部门和业务形成的协作流程，想重新搭建又需要时间磨合，最终选择成立专业的团队，基于采购的系统二次开发。

公司后来的态度明确，坚定的实现业务数字化，无论过程需要踩多少坑。



**4**



拉长时间线观察不同的企业，虽然发展的过程都很独特，但也能找到一些共同点：

**在正确的方向，始终坚定不摇摆。**

但什么方向才算正确？听过比较合理的说法：**跟随趋势走一步看一步**，需要分析和判断变化，才能平稳的应对和生存。

现在看过去，似乎是云淡风轻。

但从当时去分析：什么样的决策，才能穿越周期的影响？曾经入职过的一家公司，当时的老板经常说：

**看问题要尊重常识，做决策要敬畏因果。**

公司起步阶段做信息化产品，互联网存量竞争做数字化转型，人工智能的浪潮中做行业服务，在起起落落中生存十二年。
